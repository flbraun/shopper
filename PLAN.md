## 2. Dependencies

Runtime:
- `sqflite`, `path`: database
- `shared_preferences`: settings
- `dynamic_color`: Material You colors taken from the OS
- `flutter_localizations` (part of the SDK) + `intl`: i18n
- `material_ui`: Flutter's Material library. Since Flutter 3.47 it is a separate package and no longer `package:flutter/material.dart`; `dynamic_color` already depends on it. The Material/Cupertino translations (`GlobalMaterialLocalizations.delegates`) also come from it. `flutter_localizations` stays only because the code generated by `gen-l10n` imports it.

No state-management package; plain `ChangeNotifier` + `ListenableBuilder` from the Flutter SDK. No `INTERNET` permission in the release manifest.

Dev: `flutter_test`, `flutter_lints`, `sqflite_common_ffi` (DB tests run on the host).

F-Droid compatibility: only OSS dependencies, no Google Play Services or Firebase, signing config in an uncommitted `android/key.properties`, Flutter version pinned in the repo so builds can be reproduced.

## 4. Data model (sqflite, schema v1)

```sql
CREATE TABLE lists (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT    NOT NULL,
  name_key    TEXT    NOT NULL UNIQUE,     -- lower-cased trimmed name: no duplicate list names
  position    INTEGER NOT NULL,            -- order on the title screen
  created_at  INTEGER NOT NULL             -- epoch ms
);

CREATE TABLE items (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  list_id     INTEGER NOT NULL REFERENCES lists(id) ON DELETE CASCADE,
  text        TEXT    NOT NULL,
  struck      INTEGER NOT NULL DEFAULT 0,
  created_at  INTEGER NOT NULL             -- drives "added earliest/latest"
);
CREATE INDEX idx_items_list ON items(list_id);

CREATE TABLE dictionary (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  text        TEXT    NOT NULL,
  text_key    TEXT    NOT NULL UNIQUE,     -- lower-cased trimmed text
  created_at  INTEGER NOT NULL
);
```

- `PRAGMA foreign_keys = ON` is set in `onConfigure`.
- Case-insensitive uniqueness uses a lower-cased `*_key` column filled by Dart's `toLowerCase()`, because SQLite's `NOCASE` only folds ASCII (it would treat "Äpfel" and "äpfel" as different).
- The dictionary is insert-only (`INSERT OR IGNORE`). Nothing deletes from it, including deleting a list or using the broom.
- Schema changes go through `onUpgrade` with an incrementing version.

## 5. Settings (shared_preferences, app-wide)

| Key | Values | Default |
|---|---|---|
| `item_order` | `az`, `za`, `addedEarliest`, `addedLatest` | `az` |
| `struck_placement` | `inPlace`, `moveToBottom` | `moveToBottom` |

A settings screen is reached via a gear icon in the title screen's app bar. It has two radio groups, one per setting. Changes apply immediately.

## 6. Look and feel: following the OS

- **Colors:** `DynamicColorBuilder` uses the system's Material You palette (wallpaper colors). If it isn't available, it falls back to a fixed seed color.
- **Light/dark:** `ThemeMode.system`, so the app follows the OS dark-mode setting.
- **Font size / display size / bold text:** the system text scaling is used as is; nothing in the app overrides it.
- **Language:** the app follows the system locale (`de*` → German, everything else → English).
- **Launcher icon:** placeholder for now. It is an adaptive icon, so it also picks up Android's themed-icon setting.

## 7. Screens and behavior

### 7.1 Title screen (all lists)
- `AppBar("Shopper")` with a settings action.
- **Add button above the first list.** It opens a dialog asking for the list name. The name is trimmed, and Create is disabled while the trimmed name is empty or matches an existing list name (case-insensitive). In that case the field shows "A list with this name already exists." (de: "Eine Liste mit diesem Namen existiert bereits."). The new list is appended at the bottom (`position = max + 1`).
- Lists can't be renamed; to fix a name, delete the list and create it again.
- **Empty state:** with no lists, a small text "No lists yet." (de: "Noch keine Listen.") is centered horizontally and vertically. The add button stays visible.
- One `Card` per list, in `position` order:
  - the list name
  - an inline preview of **unstruck items only**, in the app-wide item order, comma-joined, max 2–3 lines with an ellipsis
  - below the preview, the status `x/y` (x = struck, y = total)
- Tapping a card opens the list.
- **Drag and drop** (long-press to start a drag):
  - Moving a card between other cards reorders the lists, and the new `position`s are saved.
  - While a drag is active, a **bin** target appears at the bottom of the screen. Dropping a list on it deletes the list and its items **immediately, with no confirmation or undo** (items cascade; the dictionary is untouched).
  - Implementation note: Flutter's `ReorderableListView` has no external drop targets, so this uses `LongPressDraggable` + `DragTarget` for the card slots and for the bin, with auto-scroll near the screen edges.

### 7.2 List detail screen
- `AppBar` with the list name.
- **Broom** (`Icons.cleaning_services`) above the items:
  - Tapping it immediately deletes all struck items of this list.
  - For 5 seconds the broom becomes an **undo** icon (`Icons.undo`). Tapping it restores the deleted items exactly (same text, struck state and `created_at`, so they sort back into place). After 5 s the icon reverts to the broom.
  - Restoring re-inserts in-memory copies of the deleted rows. Leaving the screen ends the undo window.
- **Empty state:** with no items, a small text "No items yet." (de: "Noch keine Einträge.") is centered horizontally and vertically. The add field stays visible.
- **Items** (`ListView.builder`):
  - Tapping an item toggles strike-through (`lineThrough` + dimmed color).
  - Order: A–Z / Z–A or by `created_at`. A–Z is case-insensitive and puts accented letters next to their base letter (Ä with A, ß as ss), since Dart has no built-in locale collation.
  - `move_to_bottom`: unstruck items (sorted) followed by struck items (sorted by the same rule). `in_place`: one list sorted only by the order rule.
  - Items can't be edited or deleted individually; only the broom removes them.
- **Add field** pinned at the bottom, above the keyboard:
  - Input is always trimmed before adding. If it is empty after trimming, nothing is added. Otherwise the item is added and `INSERT OR IGNORE`s it into the dictionary.
  - **Suggestions** while typing: dictionary entries that contain the input, case-insensitive. "Starts with" matches come first, then alphabetical, up to ~8 entries. Entries already on the list are *not* hidden. Tapping a suggestion adds it (the same path as submitting).
  - **Duplicate check:** if the list already has an item with the same text (case-insensitive, trimmed), a dialog says the item is already on the list and asks whether to add it a second time. "Add anyway" or "Cancel". This applies whether the existing item is struck or not. "Add anyway" always adds a **second, new, unstruck** item; the existing item stays unchanged, so a struck one stays struck until the broom removes it.
  - The field keeps focus after adding.

### 7.3 i18n
- `flutter gen-l10n` with ARB files for `en` (template) and `de`. Every user-facing string goes through `AppLocalizations`; none are hard-coded.
- `android:label` stays `Shopper` in both languages.
- **Per-app language:** `android/app/src/main/res/xml/locales_config.xml` (en, de) is referenced via `android:localeConfig` in the manifest, and `generateLocaleConfig` is off. Users can then pick the app's language in Android Settings → Apps → Shopper → Language, separately from the system language. The app reads the resulting locale through Flutter's normal locale resolution; there's no in-app language picker.

## 8. Build and release
- `flutter create --org de.flbraun --project-name shopper --platforms android .`, then set the label, `namespace`/`applicationId` and SDK levels.
- Release signing via `android/key.properties` + keystore, both git-ignored.
- `flutter build apk --release` (one universal APK).
- `.gitignore` extended with the standard Flutter/Android entries.
